# 코드 Wiki 파일

> 2026-09-28에 코드 그래프·코드 Wiki 기능을 제거했다. 이 문서는 당시 동작의 기록으로만 남긴다.

코드 Wiki는 활성 Rust 코드 그래프에서 읽을 수 있는 Markdown을 만든다. 에이전트는 목차에서 필요한 모듈을 고르고 원본 코드 위치로 이동할 수 있다. 업무 의미나 호출 관계를 AI로 추측한 설명은 포함하지 않는다.

## 만들고 읽기

1. 로컬 작업의 Rust 파일을 에디터로 연다.
2. 코드 그래프를 만들거나 새로 고침해 준비 상태로 만든다.
3. **코드 Wiki**에서 **전체 생성**을 실행한다. 현재 파일만 갱신할 때는 해당 동작을 사용한다.
4. 목차 또는 현재 문서를 연다. 파일은 작업 worktree의 `docs/codebase/`에 남는다.

```text
docs/codebase/
  index.md
  modules/
    src-tauri/src/runner/mod.rs.md
    src-tauri/src/codegraph/query.rs.md
```

기존 **Wiki** 화면의 폴더 연결에서 이 `docs/codebase` 디렉터리를 선택하면 같은 Markdown을 볼 수 있다. 생성 기능은 폴더 등록이나 임베딩을 자동으로 수행하지 않는다. 프로젝트 전체 폴더가 이미 Wiki에 연결됐다면 중첩 폴더를 다시 연결할 필요가 없다.

에이전트에는 `docs/codebase/index.md`부터 읽도록 안내한다. 문서의 근거 파일·심볼·참조를 따라가고, 수정 결정 전에 현재 소스를 확인한다. 생성된 Markdown은 생성 시점의 스냅샷이며, 파일만 열었다고 현재 코드와 같다는 보장은 없다.

## 최신성

- **없음**: 아직 생성되지 않은 문서.
- **최신**: 문서 checksum과 현재 그래프·소스 fingerprint가 일치.
- **오래됨**: 생성 이후 소스 또는 관련 Cargo/툴체인 설정이 변경됨. 그래프를 먼저 새로 고침하고 문서를 갱신한다.
- **충돌**: 직접 작성한 파일이 생성 경로를 차지하거나, 생성 문서의 내용/metadata가 바뀌어 자동으로 덮어쓸 수 없음.
- **소스 삭제됨**: 원본이 없어졌지만 이전 문서는 보존됨. 삭제가 맞는지 사용자가 확인한다.

첫 버전은 전체 그래프 fingerprint로 보수적으로 판정한다. 한 파일이 바뀌어 여러 문서가 오래됨으로 표시될 수 있다. 현재 파일만 갱신해도 나머지 문서가 자동으로 최신이 되지는 않는다. 저장되지 않은 편집 내용은 그래프나 Wiki에 들어가지 않는다.

## 직접 작성한 설명과 오류 처리

생성 페이지는 자동화가 관리한다. 설계 이유·주의사항·작업 메모는 다른 Markdown에 작성하고 연결한다. 일반 편집으로 내용이나 metadata가 바뀌면 충돌로 표시해 보존한다. checksum은 의도적인 위조를 방지하는 서명은 아니다.

충돌 파일을 덮어쓰려면 먼저 필요한 내용을 다른 경로에 보관하고 충돌을 해소한 뒤 다시 생성한다. 기능 자체에는 강제 덮어쓰기나 자동 삭제가 없다.

갱신은 파일 하나씩 원자적으로 교체하며 여러 페이지가 하나의 트랜잭션은 아니다. I/O 오류가 발생하면 일부 페이지만 갱신됐을 수 있다. 오류 원인을 해결한 뒤 다시 실행하면 나머지 페이지와 목차를 복구한다. 중단된 프로세스의 lock이 남으면 오류에 표시된 경로와 실제 실행 상태를 확인한 뒤 정리한다. 앱은 lock을 임의로 삭제하지 않는다.

현재 안전한 생성은 Unix 로컬 작업을 대상으로 한다. 비 Unix·원격 작업·TypeScript 문서는 이 생성 경로의 지원 범위가 아니다. 소스 수·문서 크기 제한을 넘으면 누락된 결과를 성공으로 내보내지 않고 오류로 알린다. 도구 바이너리나 프로젝트 밖 설정까지 추적하는 재현성 보장은 없다.

각 페이지는 심볼 200개와 직접 참조 100개까지 보여준다. 더 많은 항목이 있으면 목록에 생략 표시를 남기므로, 전체 관계를 확인할 때는 코드 그래프와 원본 소스를 함께 읽는다.

한 번에 만드는 문서의 전체 크기와 그래프 데이터에도 메모리 보호 상한이 있다. 출력 합계나 기존 문서 합계가 각각 16 MiB를 넘는 경우 등을 포함하며, 이때 생성은 오류로 중단한다. 개별 문서가 작다고 무제한으로 한꺼번에 생성할 수 있는 것은 아니다.

구현 계약과 한계는 설계 0064에 있다. 에이전트의 토큰 절감과 분석 정확도는 이후 동일 과제 비교로 측정해야 한다.
