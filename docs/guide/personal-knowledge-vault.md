# 개인 지식창고

개인 지식창고는 직접 모은 자료와 검토한 지식을 하나의 디렉터리에 쌓는 기능이다. 자료를 읽는 Wiki와 다음 작업에서 참고하는 메모리가 같은 문서와 출처를 사용한다. macOS 로컬 Desktop v1의 구현과 개발 빌드 검증을 완료했다. 기본 기능은 기존 구현 기록, 주제별 Markdown 작성과 읽기는 WIKI 구현·검증 기록을 따른다.

## 문서와 그래프 사용하기

Wiki의 기본 **문서** 탭은 연결된 창고 폴더의 Markdown 파일을 직접 읽는다. **관리**에서 창고 폴더를 연결한 뒤 사용한다. 하위 `wiki/`에 없는 문서도 목록과 그래프에 나타나며 파일을 옮길 필요가 없다.

- 창고를 열면 **진입 문서**가 바로 열린다. 거기서 관계 버튼과 본문 링크로 파고드는 것이 기본 동선이고, 문서를 고르는 단계는 없다. 진입 문서는 **관리 → 창고 폴더 → 진입 문서**에서 정한다(기본 `위키-시작.md`). 파일 이름만 적으면 위키 폴더가 어디에 있든 찾고, 그 문서가 없으면 역링크가 가장 많은 문서를 연다.
- 제목·본문·별칭으로 검색하거나 태그로 좁힌다. 목록 또는 그래프의 문서를 선택하면 제목·표·목록·코드가 렌더링된다. 링크가 끊긴 문서는 진입 문서에서 닿을 수 없으므로 목록과 검색으로 찾는다.
- **관련 문서**, **이 문서를 참조하는 문서**, 본문의 상대 Markdown 링크로 이동한다. `[[위키 링크]]`는 관계 버튼에서도 따라갈 수 있다.
- 그래프는 **3D**로 시작한다. 별 모양 문서를 누르면 본문을 열고 해당 문서로 시점을 옮긴다. 드래그로 회전, 휠로 확대, 우클릭 드래그로 이동한다. **화면 맞춤**은 현재 표시된 문서를 한 화면에 모은다. **문서 이동** 선택 상자는 키보드로도 사용할 수 있다.
- **2D / 3D**를 전환해도 문서 선택·검색·태그·연결 범위를 유지한다. 문서 제목은 선택하거나 가리킬 때 표시한다. 3D를 사용할 수 없거나 렌더링이 중단되면 2D로 돌아오며, **3D** 버튼으로 다시 시도할 수 있다. **그래프 접기**는 읽기 영역을 넓힌다.
- **새 문서**에서 기존 폴더 아래 `.md` 경로와 본문을 입력하고 **문서 저장**한다. 같은 경로가 이미 있으면 덮어쓰지 않는다.
- **원문 편집**은 frontmatter를 포함한 현재 파일을 연다. 외부 편집과 충돌하면 수정 내용을 남겨 두고 저장을 거절한다. 편집을 계속하거나 내용을 복사해 두고 **편집 취소 → 수정 버리기** 후 새로 고침한다.
- **삭제 → 휴지통으로 이동**은 원본 파일을 OS 휴지통으로 보낸다. 다른 문서의 참조는 자동 삭제하지 않으며 **연결 점검**에 끊어진 링크가 표시된다. 휴지통 작업 실패 시 원본 위치로 복구하고, 복구 위치가 이미 차 있으면 보존 경로를 알린다. 휴지통에서 복원한 뒤 **문서 새로 고침**하면 다시 나타난다.
- 앱에서 저장·삭제하면 문서 목록·검색·그래프를 갱신한다. 하네스나 다른 에디터에서 바꿨으면 **문서 새로 고침**한다. 저장 성공과 후속 목록 갱신 실패는 따로 표시한다.

관계 해석에는 Python 3.10 이상과 홈의 `.codex/skills/knowledge-harness` 또는 `.claude/skills/knowledge-harness`가 필요하다. 기존 `위키-그래프.html`/JSON은 배포용 스냅샷으로 남으며 앱은 이를 덮어쓰지 않는다. 생성물을 최신으로 공유하려면 하네스로 다시 생성한다.

로컬 macOS에서 사용하며 원격 세션은 접근하지 않는다. 문서당 2MiB, 탐색 1,000문서·원문 합계 16MiB, 그래프 표시 최대 200문서이며 검색/연결 범위로 좁힐 수 있다. 원문 HTML 실행·외부 이미지 자동 로드·Mermaid 실행은 제공하지 않는다. 다른 볼륨의 창고에서 휴지통 준비가 실패하면 원본을 유지하고 오류를 표시한다.

아래 자료 등록·출처·범위 설명은 **자료** 탭과 기존 색인 기능에 관한 것이다. 문서 편집이 자료 공개 범위를 자동 변경하지 않는다.

## 연결하고 자료 쌓기

1. **Wiki → 개인 지식창고** 또는 **설정 → 지식창고**에서 디렉터리를 선택한다. 선택한 경로를 확인한 뒤 **연결**한다.
2. **디렉터리 스캔**으로 기존 자료와 새로 넣은 파일을 등록한다. 디렉터리 밖 파일은 **자료 추가 → 파일 선택**으로 복사한다. 디렉터리 안 파일은 원래 위치에서 등록한다.
3. 직접 작성한 내용은 **텍스트 자료**, 조사한 링크는 **URL + 메모**로 넣는다. URL은 주소와 메모를 저장하며 페이지를 자동으로 가져오지 않는다.
4. **자료함**에서 1~5개 자료를 선택해 **위키 초안 만들기**로 이어간다. 직접 작성하려면 자료 상세의 **노트 만들기**를 사용한다. 원자료와 위키 문서는 별도로 남는다.

자료는 기본으로 **나만 보기**다. **이 프로젝트**는 등록한 프로젝트에서, **모든 프로젝트**는 로컬 프로젝트 전반에서 참고할 수 있다는 뜻이다. 출처가 더 좁은 범위에 있으면 파생 노트의 범위를 넓힐 수 없다. 공개 범위 변경은 AI 분석 동의를 대신하지 않는다.

Markdown·텍스트·CSV 중 UTF-8 2 MiB 이하는 본문 검색 대상이다. 그 밖의 파일은 이름 등 메타데이터로 찾고 **원본 열기**로 확인한다. 한 파일 100 MiB, 한 번에 20개·200 MiB까지 가져온다. 스캔은 10,000개 또는 텍스트 1 GiB에서 일부 결과와 이유를 남긴다.

## 검토하고 보존하기

WIKI의 기본 화면은 **위키 문서**다. **자료함**에서 고른 자료는 작성 단계로 그대로 이어진다. 추가에 성공한 자료가 1~5개이면 선택 상태로 넘기고, 5개를 넘으면 분석할 자료를 직접 고른다. 자료 추가만으로 모델을 실행하지 않는다.

**위키 초안 만들기**에서 입력 자료, 분석 모델과 결과 범위를 확인하고 이번 실행에 동의한다. 같은 주제의 자료는 하나의 Markdown 초안으로 종합하고, 주제별로 최대 5개를 제안한다. 나만 보기 자료를 포함한 결과는 나만 보기 범위를 유지한다. **분석에 사용한 자료**는 입력한 자료 목록이며 문장별 검증이나 인용을 보증하지 않는다.

**검토할 초안**에서 주제별 본문을 미리 보거나 Markdown으로 편집한다. 새 문서 또는 기존 노트를 선택하고, 기존 노트라면 현재 내용과 기준 해시를 대조한다. **저장 내용 확인**으로 backend가 검토한 최신 내용을 읽고 **MD 저장**한다. 본문·대상·범위를 수정하면 다시 확인해야 한다. 저장 전 초안은 데이터베이스에만 있고 디렉터리에는 파일을 만들지 않는다. **넘기기**는 원자료를 변경하지 않는다.

저장하면 반환된 문서가 바로 열린다. 실제 파일은 `notes/<문서 ID>/<버전 ID>.md`이며, 출처 목록은 시스템이 관리한다. 저장 후 문서를 읽지 못했을 때는 읽기만 다시 시도한다. 저장 응답이 유실되면 저장 상태를 먼저 조회하며, 진행 중이거나 결과가 불명확하면 설정의 **미완료 작업 확인**으로 복구 상태를 확인한다.

화면을 다시 열어도 최근 수동 분석의 상태와 이미 생성된 초안을 확인할 수 있다. 대기·진행 상태 조회는 모델을 실행하지 않는다. 일부 초안을 만든 뒤 분석이 실패했으면 생성된 초안부터 검토한다. 새 분석은 현재 자료를 다시 준비하고 새 실행 동의를 받아야 한다. 앱 재시작 후 분석을 자동 재개하지 않으며 저장 전 편집 내용의 재시작 복원은 지원하지 않는다.

직접 작성한 노트는 **노트 수정**으로 갱신한다. 저장하면 새 버전이 생기고 이전 버전과 출처가 유지된다. 수정하는 동안 다른 곳에서 노트나 출처가 바뀌면 저장을 멈추므로 최신 내용을 다시 열어 확인한다. 연결된 문서 이름을 누르면 해당 문서로 이동하고 **출처 버전 열기**로 당시의 파일을 확인한다.

원자료를 기존 노트에 연결하려면 **노트 만들기 → 기존 노트에 연결**에서 대상을 고른다. 불러온 내용과 기준 버전을 확인한 뒤 **기존 노트에 저장**한다. 기존 출처에 새 자료가 추가되고 새 노트 버전이 생긴다. 원자료보다 넓은 범위의 노트에는 연결할 수 없다.

외부 편집으로 파일 내용이 바뀌면 기존 버전을 자동으로 덮어쓰지 않는다. 변경을 확인하고 **새 버전으로 등록**한다. 확인 이후 다시 바뀐 파일은 재확인이 필요하다. 새 버전의 기본 범위는 나만 보기다. **보관**은 문서를 검색·회수에서 제외하고 파일을 유지한다. **복원**으로 다시 확인할 수 있다.

**연결 해제**는 파일을 삭제하지 않는다. 다른 디렉터리를 사용할 때는 현재 연결을 먼저 해제한다. 창고나 프로젝트를 이동·복제한 경우 경로 이름만 같다고 기존 권한이 자동으로 이어지지는 않는다.

창고 위치를 옮겼다면 설정의 **새 위치로 연결**에서 이전 위치와 새 위치를 대조하고 현재 버전을 선택한다. 서버가 선택한 파일의 해시를 다시 확인하며, 다시 연결한 자료의 공유 범위는 새로 지정해야 한다. **미완료 작업 확인**은 파일과 카탈로그 상태를 대조한다. 필요한 파일이 없거나 출처·기준 버전이 바뀌었으면 충돌로 남기고 기존 파일을 유지한다. 충돌 파일을 임의로 삭제해 해결하지 않는다.

메모리는 **Wiki › 메모리**에서 읽는다. 개인 창고의 내용은 기존 무범위 검색·임베딩으로 자동 공급하지 않는다.

## 다음 작업에 참고하기

로컬 작업 작성창에서 요청을 작성하고 **관련 자료 미리보기**를 연다. 문서·버전 해시·조회 시점·발췌를 확인하고 원치 않는 자료를 제외한다. 실제 전송 직전에 범위와 파일 내용을 다시 검사한다. 그사이 바뀐 자료는 생략하며 다른 자료로 대체하지 않는다. 한 번에 최대 5개, 문서마다 2 KiB, 합계 8 KiB의 텍스트를 전달한다.

**이번 작업만**은 현재 입력을 자동 지식 축적에 사용하지 않도록 지정한다. **나만 보기 자료 첨부**는 선택한 비공개 자료를 현재 요청에만 전달한다. 이 자료가 섞인 회차는 자동 정리에서 제외한다. 입력을 바꾸면 선택 내용을 다시 확인한 뒤 전송한다. 작업의 전달 기록에서는 당시 발췌·해시·실행 회차와 전달 상태를 확인한다. 전달 성공은 모델이 답변에 실제로 인용했다는 뜻이 아니며, 인용을 확인하지 못한 경우 그대로 표시한다.

## 백업과 실행 한계

내용 파일과 앱의 SQLite 카탈로그를 함께 백업해야 연결, 버전 관계, 공개 범위, 동의와 승인 이력을 복구할 수 있다. 파일만 복사한 폴더는 읽을 수 있는 자료 모음이지만 기존 권한 이력 전체를 복원하지는 않는다. 앱을 종료한 상태에서 파일과 데이터베이스를 일관되게 백업한다. `wiki/` 아래 위키 문서는 파일이 정본이라 앱이 옛 본문을 보관하지 않는다 — 스캔은 바뀐 해시와 이전 해시만 이벤트로 남기므로, 본문 이력은 창고 폴더의 git·백업이 맡는다.

AI 제안은 설정된 provider와 명시적 동의가 필요하다. 추적하지 못한 입력, 나만 보기 자료, 이번 작업에만 사용하도록 지정한 입력이 섞인 회차는 자동 분석에서 제외한다. 재시작 때문에 중단된 분석은 자동 재실행하지 않는다. 실제 provider 품질·비용은 가짜 CLI 검증과 별도로 확인해야 한다.

자동 제안의 현재 허용 경로는 동의 이후 시작한, 출처 확인이 완료된 초기 대화다. 도구 결과·이전 대화·첨부·스킬 확장이 섞이거나 실행 기록이 불완전하면 제외한다. PTY 입력과 해석하지 못한 Codex 이벤트도 자동 분석하지 않는다. 이런 자료는 **자료함 → 위키 초안 만들기**에서 명시적으로 선택해 정리할 수 있다.
