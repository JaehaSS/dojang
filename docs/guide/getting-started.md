# 시작하기

설치부터 첫 작업을 승인하기까지 한 번 따라가는 문서입니다. 10분쯤 걸립니다.

## 1. 미리 있어야 하는 것

Dojang은 에이전트 CLI를 **직접 실행**하는 도구입니다. 앱이 CLI를 대신 설치해 주지는 않습니다.

| 필요한 것 | 확인 방법 |
|---|---|
| **git** | `git --version` |
| **에이전트 CLI 하나 이상** | `claude --version` / `codex --version` / `agy --version` |
| 작업할 **git 저장소** | 로컬에 clone 되어 있어야 합니다 |

에이전트 CLI는 각자 로그인/API 키 설정이 끝나 있어야 합니다. 터미널에서 `claude`를 쳤을 때
정상 동작한다면 Dojang에서도 동작합니다. **터미널에서 안 되면 Dojang에서도 안 됩니다** —
이건 Dojang 문제가 아니라 CLI 설정 문제입니다.

## 2. 설치

1.0은 **macOS Apple Silicon 전용**입니다.

1. [릴리스 페이지](https://github.com/JaehaSS/praxis/releases/latest)에서 `Dojang_<버전>_aarch64.dmg`를 받습니다.
2. dmg를 열고 `Dojang.app`을 `응용 프로그램` 폴더로 옮깁니다.
3. 처음 열 때는 더블클릭하지 말고 **우클릭 → 열기**를 누른 뒤, 경고 창에서 다시 **열기**를 누릅니다.
   이 빌드는 ad-hoc 서명만 돼 있고 Apple 공증은 받지 않았습니다.

다른 플랫폼이거나 서명 경고를 피하고 싶다면 소스에서 직접 빌드합니다. Node.js 22 또는 24와
Rust stable, 그리고 그 OS의 Tauri 사전 요구 사항이 필요합니다.

```sh
npm ci
npm run tauri build
```

macOS라면 `src-tauri/target/release/bundle/macos/Dojang.app`이 나옵니다. 같은 경로의 `dmg/`에
설치용 이미지도 함께 생깁니다.

> 반복해서 빌드·검증된 환경은 **macOS Apple Silicon**뿐입니다. Windows·Linux·Intel Mac은 코드
> 분기는 있지만 빌드 기록이 없어, 처음 시도하면 손볼 곳이 나올 수 있습니다.

따로 준비할 서버는 없습니다. 작업은 전부 이 기계에서 돕니다.

## 3. 화면 익히기

앱을 열면 **홈 화면**이 나옵니다.

```
┌─ 사이드바 ──────┬─ 메인 ────────────────────────────────┐
│  + 새 작업       │   ✦ 인사말                            │
│                  │                                       │
│                  │   [ 통계 ]  총 작업 · 진행 중 · 성공률 │
│  인사이트        │                                       │
│  Wiki            │   [ 오늘 할 일 ]                      │
│                  │   [ 승인 대기 ] [ 최근 작업 ]         │
│                  │                                       │
│ ─── 프로젝트 ─── │                                       │
│  praxis      +   │  ┌─ 컴포저 ─────────────────────────┐ │
│   ● 작업 1       │  │ [레포][브랜치][격리][실행환경]    │ │
│   ● 작업 2       │  │ 지시문을 여기에…          [생성] │ │
│  Dojang · 설정   │  └──────────────────────────────────┘ │
└──────────────────┴───────────────────────────────────────┘
```

사이드바 위쪽 둘(**인사이트 · Wiki**)이 세션에 속하지 않는 화면의 진입점이고,
그 아래는 최근 세션과 **프로젝트별로 묶인 진행 중 작업** 목록입니다. 프로젝트 옆 `+`로 그 레포에
바로 새 작업을 만들 수 있습니다. 나머지(스킬·MCP·모바일·스케줄)는 맨 아래 **설정**
안에 있습니다. Obsidian vault·Gmail 연동은 설정이 아니라 **Wiki › 연결** 탭에 있습니다.

작업 카드를 클릭하면 **작업 화면**으로 바뀝니다.

```
┌─ 사이드바 ──┬─ 대화 · 활동 ────────┬─ 코드 열 ──────────────┐
│  + 새 작업   │                      │ [파일][프리뷰][작업정보]│
│              │  에이전트와 주고받은  │                        │
│  …           │  대화가 여기 쌓입니다 │  파일 트리 + 에디터    │
│              │                      │  또는 Diff             │
│ ● 작업 1 ←   │                      │                        │
│              │  ┌────────────────┐  │  ─────────────────────  │
│              │  │ 이어서 지시…   │  │  터미널 도크 (Ctrl+`)  │
│              │  └────────────────┘  │                        │
└──────────────┴──────────────────────┴────────────────────────┘
                                        ↑ Alt+Ctrl+S 로 접기
```

가운데에서 에이전트와 대화하고, 오른쪽 **코드 열**에서 결과를 봅니다. 코드 열의 탭 세 개는
각각 **파일**(트리와 에디터), **프리뷰**(디자인 모드), **작업정보**(상태와 승인 버튼)입니다.

## 4. 첫 작업 만들기

앱을 열면 **홈 화면**이 나옵니다 — 인사말, 통계, 최근 작업 목록이 보입니다.

화면 하단의 **컴포저**(입력창)에서 작업을 만듭니다. 입력창 위에 칩 몇 개가 붙어 있습니다:

| 칩 | 무엇을 고르나 | 처음이라면 |
|---|---|---|
| **레포** | 작업할 git 저장소 | 로컬 저장소 경로를 지정 |
| **브랜치** | 어디서 갈라져 나올지 | 기본값(현재 브랜치) |
| **워크트리 격리** | 격리 worktree를 팔지, 레포에서 직접 실행할지 | **격리**(기본값) 유지 |

그다음 지시문을 씁니다. 평소 에이전트에게 시키듯 쓰면 됩니다:

```
src/utils/date.ts 의 formatDate 가 UTC 기준으로 나오는데
로컬 타임존 기준으로 바꾸고 테스트도 같이 고쳐줘
```

**작업 생성**을 누르면 끝입니다.

### 이때 뒤에서 벌어지는 일

```
<레포>/.praxis/worktrees/<작업명-타임스탬프>/   ← 여기에 worktree가 파집니다
브랜치: praxis/<작업명>-<타임스탬프>            ← 여기에 커밋됩니다
```

에이전트는 **이 worktree 안에서만** 움직입니다. 원본 레포의 파일도, 현재 브랜치도 건드리지
않습니다. 그래서 작업이 산으로 가도 폐기 한 번이면 흔적 없이 사라집니다.

## 5. 진행 지켜보기

사이드바에 작업이 뜨고 상태가 바뀝니다:

```
Queued → Running → AwaitingReview → (승인) Finalizing → Done
                                  → (폐기)            Discarded
```

작업 카드를 클릭하면 앞서 본 **작업 화면**이 열립니다. 가운데에서 에이전트가 무엇을 하고
있는지 보이고, 도중에 끼어들어 이어서 지시할 수도 있습니다.

작업이 끝나면 상태가 **AwaitingReview**가 되고 알림이 옵니다. 여기서 멈춥니다 —
**사람이 보기 전에는 아무것도 머지되지 않습니다.**

## 6. 검토하고 승인하기

코드 열에서 **Diff**를 열면 변경 내용이 나옵니다. 한 화면에 겹쳐 보는 unified와 좌우로
나눠 보는 split 둘 다 됩니다. 승인·폐기 버튼은 **작업정보** 탭에 있습니다.

| 결정 | 결과 |
|---|---|
| **Approve** | worktree의 변경을 커밋하고 원래 브랜치에 머지합니다. 충돌이 나면 자동으로 되돌리고 알려 줍니다 |
| **Discard** | worktree와 브랜치를 통째로 지웁니다. 원본은 그대로입니다 |

승인이 끝나면 `Done`, 폐기하면 `Discarded`가 되고 사이드바에서 정리됩니다.

여기까지가 한 사이클입니다. 이제 작업을 **동시에 여러 개** 돌리면 됩니다 — 최대 8개까지 각자
자기 worktree에서 병렬로 굴러갑니다.

## 7. 알아두면 편한 단축키

| 키 (Windows · Linux) | 동작 |
|---|---|
| `Ctrl+K` | Quick Open — 어디서든 전체 검색 |
| `Ctrl+P` | Quick Open (파일만) — 작업이 열려 있을 때 |
| `Ctrl+B` | 파일 트리 접기/펼치기 |
| `Alt+Ctrl+B` | 사이드바 접기/펼치기 |
| `Alt+Ctrl+S` | 코드 열 접기/펼치기 |
| ``Ctrl+` `` | 터미널 도크 접기/펼치기 |
| `Ctrl+Alt+C` | 음성 명령 (누르고 있는 동안 녹음) |
| `Ctrl+Alt+D` | 음성 받아쓰기 (누르고 있는 동안 녹음) |

> macOS에서 쓴다면 `Ctrl` 자리를 `⌘`로, 음성은 `⌥C` / `⌥D`로 읽으세요.
