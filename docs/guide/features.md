# 기능 카탈로그

Dojang에 있는 기능을 도메인별로 정리했습니다. **전부 쓸 필요는 없습니다** — 1~3번이 핵심이고
나머지는 필요할 때 꺼내 쓰는 것들입니다.

사이드바에 상시 노출되는 화면 진입점은 **인사이트 · Wiki** 둘과 **설정**이고,
그 아래가 최근 세션·프로젝트별 작업 목록입니다. 나머지 기능은 작업 화면과 설정 탭 안에 있습니다
(`src/components/ide/Sidebar.tsx`).

---

## 핵심

### 1. 작업 오케스트레이션

여러 에이전트를 동시에 굴리는 본체입니다.

- **격리 실행** — 작업마다 `.praxis/worktrees/` 아래 git worktree를 파고 `praxis/<이름>-<나노초>`
  브랜치에 커밋합니다. 승인 전까지 원본 브랜치는 그대로입니다 (`src-tauri/src/worktree/mod.rs`).
- **동시 실행 상한** — 기본 8개, 설정에서 1~64까지. 한도에 닿으면 생성이 거부됩니다
  (`src-tauri/src/commands.rs`, 설정 키 `max_concurrent`).
- **벤더 선택** — `claude`(Claude Code) · `codex`(Codex) · `agy`(Antigravity · Gemini) 셋을 작업마다
  고릅니다. 커스텀 명령도 지정할 수 있습니다 (`src-tauri/src/agent/mod.rs`의 `PRESETS`).
- **직접 실행 모드** — 격리가 곤란한 작업은 레포에서 바로 돌릴 수 있습니다. 단, **사용자가 UI에서
  만든 단독 작업일 때만** 허용되고 앙상블·외부 기원(스케줄 등) 작업은 항상 격리됩니다. 직접 모드는
  승인 시 머지·정리를 하지 않습니다(되돌릴 지점이 없습니다).
- **외부 기원 작업은 대기부터** — 앱 밖에서 들어온 작업은 레포 화이트리스트를 통과해도
  `PENDING_APPROVAL`에서 멈추고, 사용자가 승인해야 실행됩니다.
- **세션 이어받기** — 터미널에서 하던 **Claude Code 세션을 골라 새 작업으로 잇습니다.** 세션홈
  (`~/.claude/projects`)을 프로젝트 → 세션 2단 트리로 보여 주고, 고른 세션을 그대로 이어받습니다.
  Dojang에 작업 행이 없던 터미널 세션도 대상입니다. 같은 세션을
  이미 물고 있는 작업이 있으면 거절하고 그 작업으로 보냅니다 — 한 세션 파일에 두 대화가 섞이는 것을
  막습니다. 5분 안에 활동한 세션은 "다른 창에서 아직 쓰는 중일 수 있다"고 확인을 받습니다.
  현재 **Claude 전용**입니다(codex는 대응 확인 전, agy는 세션 id 개념이 없어 불가).
- **작업 결과·검토** — 로컬 작업 메뉴의 결과 항목에서 산출물 경로, 변경, 검사 명령·출력 이력과 사용한 목적을 함께 확인합니다. 검사 통과와 현재 소스 여부를 구별합니다. 사람이 검토를 시작한 작업만 완료 기준 확인과 수정 요청·재검토를 거치며, 검토 완료가 Git 적용을 실행하지는 않습니다.
- **재시작 복원** — 앱이 죽어도 작업 기록은 남습니다. 돌다 만 작업은 정리됩니다.

### 2. 대화

- **턴 가드** — 에이전트가 백그라운드 작업을 남기고 턴을 끝내지 못하게 막습니다
  (`src-tauri/src/convo/turn_guard.rs`).
- **프롬프트 대기열** — 응답을 기다리는 동안 다음 지시문을 쌓아 둡니다. 세션당 FIFO, 확인·삭제·
  일시정지가 되고 **앱을 껐다 켜면 사라집니다**(메모리 큐).
- **따로 질문** — 메인 대화를 건드리지 않고 옆에서 묻습니다. 도구 없이 돌고 메인과 **동시에**
  실행됩니다.
- **체크포인트·되감기** — 되감기는 완전한 복원이 아닙니다. 파일은 체크포인트로 실제 복원하고,
  대화는 "새 세션 + 유지한 사실·버린 접근 요약 주입"으로 재구성합니다 (`src-tauri/src/rewind/`).
- **세션 중 모델·에이전트 전환**, Codex 한정 **실행 속도(fast) 설정**.
- **에이전트 토론**(부분 구현) — 한 작업에 벤더 둘을 붙여 라운드로 주고받게 합니다. 실 벤더 CLI
  왕복 수동 검증은 아직 남아 있습니다.
- **에이전트가 되묻는다**(실험, 기본 꺼짐) — 에이전트가 턴 도중 막히면 사용자에게 질문을 던지고
  답이 올 때까지 **같은 턴·같은 프로세스가 멈춰서 기다립니다.** 재개도 새 실행도 없습니다.
  로컬 Codex(dynamicTools)와 Claude Code(인앱 MCP `ask_user`) 둘 다 됩니다. macOS·Linux만 지원하고,
  Claude CLI가 질문 TTL(30분)을 끝까지 존중하는지는 아직 실측되지 않았습니다.

### 3. 검토와 승인

승인 전에 뭘 바꿨는지 보고, 안전하게 합치는 자리입니다.

- **Diff 뷰어** — unified / split 전환, hunk·파일 단위 키보드 이동(J/K, `[`/`]`), 기준점이 rebase·
  amend로 바뀌면 경고 (`src/components/DiffViewerLayout.tsx`).
- **부분 적용** — 변경 전체가 아니라 **고른 hunk만** 적용합니다. 적용 실패는 체크포인트로 자동
  원복합니다(fail-closed) (`src-tauri/src/partial/`).
- **주석 스레드** — diff의 특정 줄에 코멘트를 달고, 모아서 에이전트에게 재전송합니다.
- **벤더 리뷰** — 검토 대기 작업의 액션 줄에서 claude·codex·agy(+gemini 선택)에게 같은 diff를
  읽히고 필요하면 종합까지 받습니다. 결과는 작업에 이력으로 남습니다
  (`src/components/ide/TaskVendorReview.tsx`).
- **승인 준비도** — 승인 전에 대상 위치·보호 경로·진행 중인 git 작업·예상 충돌·원격과의 차이를
  미리 보여 줍니다. 격리 작업에만 표시되고, 실제 승인 때 보호 검사는 다시 실행됩니다.
- **자동 충돌 해결(후보 방식)** — 원본을 건드리지 않는 후보 worktree에서 에이전트가 병합·수정을
  시도하고, 앱이 독립적으로 build/test를 돌린 뒤 **사람이 채택 버튼을 눌러야** 반영됩니다.
  자동 승인은 없습니다.
- **충돌 해소기** — 파일별로 내 작업 / 기준 브랜치 / 양쪽 합치기를 고르고, 중단해 되돌릴 수
  있습니다. 충돌은 worktree 안에만 남습니다 (`src/components/ide/ConflictResolver.tsx`).
- **검증 게이트** — `.praxis/validate.toml` 또는 자동 탐지로 build/test를 돌립니다. 검사가 하나도
  없으면 "통과"가 아니라 **미검증**으로 판정합니다. 승인은 기본 소프트 게이트이고, 설정에서
  "검증 실패 시 Approve 차단"을 켜면 하드 게이트가 됩니다.
- **목표 계약** — 목표·수용 기준·중단 조건·보호 경로를 작업에 고정합니다. 이 중 **보호 경로만
  기계적으로 강제**됩니다.
- **결정 원장**(기본 꺼짐) — 승인 결과와 근거를 잇는 로컬 원장입니다.

### 4. 앙상블

같은 지시문을 여러 에이전트에게 시키고 결과를 비교합니다.

- 후보 diff를 **심판 모델**이 비교해 추천합니다. 추천 대상은 실제 후보 목록 안으로 제한됩니다.
- **조합 병합** — 승자 worktree를 베이스로 다른 후보의 hunk를 골라 얹습니다. 같은 자리를 건드리는
  hunk는 배타 그룹으로 묶여 하나만 고를 수 있고, 적용 실패 시 전부 원복합니다.
- 후보별 선택 이력과 피드백이 남습니다.

## 코드를 다루는 화면

### 5. 에디터 · 파일 · 코드 이동

- **Monaco 에디터** — VS Code와 같은 엔진. 멀티 탭, 분할 보기, 팝아웃 창(프로젝트 전용 창 포함).
- **파일 트리** — 작업 worktree 범위로 제한됩니다.
- **코드 내비게이션** — 정의·구현·사용처로 이동합니다. 언어 서버(LSP) 기반이고 창마다
  뒤로/앞으로 기록을 갖습니다. 선언 위에서 ⌘B·⌘클릭하거나 우클릭 **사용처 보기**를 고르면 사용처 목록이 열립니다. Rust·TypeScript·Python·Java에서 검증했고 Python은 참조가 제한적입니다.
- **표와 콘솔** — 팝아웃 창에서 `.parquet`을 표로 훑어보고(앞 N행 스트리밍), IPython 콘솔 도크에
  ⇧⏎로 선택 코드를 흘려보냅니다.
- **Quick Open** — 파일·작업·명령을 한 창에서 검색합니다.
- **컴포저** — `@`로 파일 멘션, `/`로 스킬 호출, ⌘L로 선택 코드 첨부, 이미지 붙여넣기, ↑↓ 히스토리.

### 6. 프리뷰 & Design Mode

화면을 에이전트에게 보여 주고, 에이전트가 직접 조작하게 하는 기능입니다.

- 프리뷰 창은 **에이전트가 필요로 할 때 자동으로 열리고** 기존 창을 재사용합니다.
- MCP 도구 7종으로 브라우저를 제어합니다 — 이동·스냅샷·클릭·입력·키 입력·대기·콘솔
  (`src-tauri/src/preview_bridge/mcp/protocol.rs`).
- 요소·에디터 영역·붙여넣은 이미지를 캡처해 프롬프트에 첨부합니다.

## 에이전트를 똑똑하게

### 7. 메모리 (파일 기반)

2026-09-13부터 메모리는 **DB 레코드가 아니라 창고 안의 파일**입니다.

- `<창고>/USER.md`(전역)와 `<창고>/<레포키>/MEMORY.md`(프로젝트)를 읽어 작업 worktree의
  `AGENTS.md`에 managed block으로 주입합니다 — 벤더별 파일을 나누지 않고 **한 파일만** 씁니다.
  옛 worktree에 남은 `CLAUDE.md`·`GEMINI.md` 블록은 회수만 계속됩니다 (`src-tauri/src/memory/file.rs`).
- 정본은 파일이라 **편집은 에디터 창**에서 합니다. Wiki의 메모리 탭은 목록·창고 루트·상한 설정과
  "정리 세션 열기"를 제공합니다 (`src/components/knowledge-vault/VaultMemoryPanel.tsx`).
- 옛 DB 메모리(3계층·FTS5·의미 검색·승인 원장)는 1.0에서 **코드째 제거했습니다.** 기존 사용자
  DB에 남은 레거시 표는 시작 시 한 번(`purge_legacy_once`) 비웁니다. 자동 수집 토글을 켤 UI
  진입점은 현재 없고, 도달 불가 상태였던 수동 회고("이 작업 회고하기")와 그 제안 목록/승인/거부
  화면은 함께 제거했습니다(아래 "알려진 제약" 참고).
- **캡슐** — 작업 인수인계용 브리핑 블록(목표 계약·상태·다음 행동·검증 요약·변경 파일)은 메모리와
  별개 마커로 계속 동작합니다.

### 8. Wiki · 지식 창고

- **Wiki** — 창고 폴더가 정본이고 DB는 색인입니다. 문서·메모리를 필터 탭으로 오갑니다.
- **그래프 탐색** — 2D와 **3D 전환**을 지원합니다(표시 상한 200개). 3D는 지연 로드됩니다.
  폴더마다 노드 색이 붙고(색 3종 + 범례), 종류·상태·범위로 거릅니다.
- **리더** — 문서를 열면 연결 근거를 줄 번호와 함께 보여 주고, 근거 줄을 누르면 그 문서의 해당
  줄로 이동합니다. 헤더의 **대화에 첨부**로 지금 보는 문서를 발췌째 프롬프트에 넣습니다.
- **검색** — 제목 → 별칭 → 경로 → 본문 순으로 순위를 매기고 어디가 맞았는지 한 줄로 보여 줍니다.
- **개인 지식 창고** — 파일 가져오기·텍스트·URL을 항목으로 넣고 증거를 붙입니다.
- **외부 소스(RAG)** — Gmail·Obsidian 커넥터가 있고 **Wiki › 연결** 탭 안에 있습니다(1.0부터
  설정이 아니라 Wiki 안). Notion은 미구현입니다. 이 연동은 위의 개인 지식 창고와 별개 백엔드이되,
  화면은 같은 Wiki 안에 탭으로 함께 있습니다.
- **퀴즈** — 에이전트 응답을 기다리는 동안(25초 이상) 복습 문제를 냅니다. 출제 소재는 현재
  **Obsidian 청크만**입니다. 응답이 와도 패널을 자동으로 닫지 않고 배지로 알립니다.

### 9. 스킬

자주 쓰는 지시문을 `/이름`으로 부르는 기능입니다.

- Dojang은 스킬을 **소유하지 않고 관측합니다** — `~/.claude/skills`, `~/.codex/skills`(구형
  `~/.codex/prompts`), `~/.gemini/commands` 등 벤더 디렉터리를 읽습니다. 프로젝트 레이어가 전역보다
  우선하고, 같은 이름은 한 줄로 접힙니다.
- 대상 CLI가 스스로 해석할 수 있으면 원문 그대로 보내고, 못 할 때만 본문을 펼쳐 넣습니다.
- 설정 > 스킬 탭에서 목록·본문을 봅니다.

### 10. MCP · LSP · 에이전트 상태

- **MCP 레지스트리** — 작업 worktree에 `.mcp.json`을 주입합니다. 사용자가 이미 둔 파일은 덮어쓰지
  않고, 시크릿은 저장하지 않습니다.
- **LSP 브리지** — 워크트리 마커로 언어를 감지해 LSP-MCP 브리지를 붙입니다(공급망 고정).
  TypeScript·Python은 npx로 붙고, Rust는 rust-analyzer가 PATH에 있어야 합니다.
- **CLI 상태** — claude·codex의 로그인 상태와 버전을 봅니다. 토큰 만료는 "로그아웃"이 아니라
  "낡음"으로 표시합니다(CLI가 스스로 갱신하므로). **agy는 노출 표면이 없어 제외**입니다.

### 11. 인터뷰

지시문이 부실할 때 앞에서 다듬는 기능입니다. **새 작업 생성 화면에서만** 쓸 수 있습니다
(`src/components/ide/Composer.tsx`). 패널 하나에 두 단계가 순서대로 있습니다.

- **1단계 · 깊게 파기** — 주관식 질문을 한 번에 하나씩 던집니다. 결과는 계약이 아니라 생각 정리
  노트로 `docs/explorations/`에 남고, 다듬은 지시문을 돌려줍니다. 라운드 상한은 백엔드가 강제합니다.
- **2단계 · 채점** — 목표·제약·성공 기준 세 축으로 모호성을 채점하고 객관식으로 물어 목표 계약
  초안을 만듭니다. 점수 계산은 모델이 아니라 앱이 합니다.
- 1단계 결과를 "지시문에 적용 → 채점"으로 2단계에 넘기거나, 처음부터 **"채점만"** 으로 1단계를
  건너뜁니다. 소프트 게이트라 하지 않아도 작업은 만들어집니다.

### 13. 인사이트

  띄웁니다. 자리는 대화 안 "작업 중" 띠 바로 아래이고, 그 대화의 턴이 도는 동안에만 뜹니다. 원천은 연결된 개인 지식창고의 `.md` 문서로, `## 절` 하나가 카드 하나입니다(코드 펜스·
  표·이미지는 빼고 500자에서 자릅니다). 직접 만든 덱 파일도 같은 자리에서 함께 읽습니다.
  설정 진입점은 **Wiki > 연결**이고, 거기서 **쓸 폴더를 골라** 범위를 좁힐 수 있습니다
  (안 고르면 전체). 창고를 연결하지 않았으면 카드가 0장입니다.

## 입력과 바깥

### 14. 음성 입력

- **누르고 있는 동안 녹음**(push-to-talk), 두 모드 — **명령**과 **받아쓰기**. 받아쓰기는 자동
  전송하지 않습니다. 기본 핫키는 macOS `Alt+C`/`Alt+D`, Windows·Linux `Ctrl+Alt+C`/`Ctrl+Alt+D`.
- **STT 서버가 필요합니다.** macOS 26+에서는 내장 SpeechAnalyzer 기반 `ohr`를 설정에서 켜고 끌 수
  있고(핫키를 누르면 그때 기동), 그 밖에는 OpenAI 호환 `/audio/transcriptions` 서버를 직접 준비해
  주소·모델·키를 넣습니다. 언어 코드는 `ko`가 아니라 `ko-KR` 형식이어야 합니다.

### 15. 모바일 PWA (베타)

- **데스크톱이 직접 서빙합니다**(루프백 + `tailscale serve`). 설정 > 모바일 탭에서 서빙 토글·포트·
  잠자기 방지·페어링 코드·세션 해지를 다룹니다.
- 폰에서 할 수 있는 것: 작업 생성·실행·승인·폐기·대화·검증. 원격 명령 토글과 무관하게 **대화는
  항상 허용**됩니다.
- 알림은 Web Push(VAPID)로 갑니다 — 검토 대기·질문 대기 상태를 알립니다.
- **실기기 페어링 런타임 검증 기록은 아직 없습니다.**
